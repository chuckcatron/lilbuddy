## Scope

### In Scope
1. Create `app/upgrade/page.tsx` — public `"use client"` page that:
   - Reads `?plan=monthly|annual` and `?uid=<tokenIdentifier>` from query params
   - Displays two plan cards: $4.99/mo and $29.99/yr with "Save 50%" badge on annual
   - Pre-selects the plan if `?plan=` is passed
   - Maps `uid` query param to `tokenIdentifier` when calling `api.stripe.createCheckoutSession`
   - Redirects to the Stripe Checkout URL returned by the action
   - Shows canceled state via `?canceled=true` query param
2. Create `app/welcome/page.tsx` — post-purchase landing page that:
   - Shows a success message
   - Displays a "Return to App" button that opens `momentum://` deep link
   - Falls back to App Store link if deep link doesn't trigger
3. Unit tests for both pages

### Out of Scope
- Stripe backend actions (Story 1 / AB#1133 — already done)
- Mobile paywall changes (Story 5 / AB#1137)
- Web paywall UI for existing habit pages (Story 4 / AB#1136)
- Stripe Price ID creation in Stripe Dashboard (manual setup)

## Constraints

- **Public pages**: Both `/upgrade` and `/welcome` are outside the `(app)` route group and do NOT require authentication. They use the root layout which wraps in `ClerkProvider` + `ConvexClientProvider`.
- **Suspense required**: Any page using `useSearchParams()` in Next.js must be wrapped in `<Suspense>` — see `billing/page.tsx:76-81` pattern.
- **No `any` types**: TypeScript strict mode is enabled.
- **Convex guidelines**: Read `convex/_generated/ai/guidelines.md` before writing any Convex-related code.
- **Deep link**: Use `momentum://` scheme. For App Store fallback, use `https://apps.apple.com/app/idXXXXXX` (replace with actual App Store ID when available, or use bundle ID `cc.getmomentum.app`).
- **Design system**: Use existing Tailwind v4 CSS variables — `var(--primary)`, `var(--border)`, `var(--card)`, `var(--muted)`, `var(--foreground)`, `var(--background)`.
- **Mobile sends `?uid=`**: The mobile paywall (`paywall.tsx:71`) sends `?uid=${user?.id}`. The `/upgrade` page reads this as `uid` and passes it as `tokenIdentifier` to the Stripe action. Do NOT rename the query param — mobile is out of scope.

## Expected Output

After this story is complete:

1. `/upgrade` page loads without authentication
2. Two plan cards displayed: $4.99/mo and $29.99/yr with "Save 50%" badge on annual
3. `?plan=annual` pre-selects the annual plan
4. `?uid=` is read and passed as `tokenIdentifier` to the Stripe action
5. Clicking a plan card calls `api.stripe.createCheckoutSession({ plan, tokenIdentifier })` and redirects to Stripe Checkout
6. After payment, Stripe redirects to `/welcome?success=true`
7. `/welcome` shows success message and "Return to App" button
8. "Return to App" opens `momentum://` deep link
9. App Store fallback link visible if deep link doesn't work
10. `?canceled=true` on `/upgrade` shows a dismissed-able banner
11. Both pages wrapped in Suspense for `useSearchParams`

## Edge Cases

- **Missing `?uid=` param**: Show an error state or disable the checkout button — don't call the action without a `tokenIdentifier`
- **Missing `?plan=` param**: Default to no pre-selection — user must click a plan card
- **Deep link failure**: Not all browsers support custom URL schemes. The "Return to App" button should attempt `momentum://` but also show a visible App Store link below it as a fallback
- **User visits `/upgrade` directly (not from mobile)**: Page should still work — show plan cards, let user enter checkout flow. The `uid` param may be missing if they navigate directly, so handle that gracefully
- **Stripe action throws**: Show an error message — don't leave the user on a loading state. Follow the `catch { setLoading(false) }` pattern from `billing/page.tsx:25-27`
- **Double-click prevention**: Disable buttons while loading to prevent duplicate checkout sessions
