### Approach Failure Recovery

- If `eslint-config-next` has peer dependency conflicts with Next 16, try `--legacy-peer-deps` and document it.
- If the `proxy.ts` rename causes Clerk middleware to stop working, check if `@clerk/nextjs` needs an update to support the proxy convention — report before continuing.
- If the proxy rename alone doesn't eliminate the build warning, check `next.config.ts` for needed `experimental.proxyPrefetch` or `skipProxyUrlNormalize` options.

### Repo-Specific Anti-Patterns

- Do NOT use `next lint` as the lint script — it was removed in Next.js 16. Use `eslint .` directly.
- Do NOT commit `middleware.ts` alongside `proxy.ts` — delete the old file.
- Do NOT add `"use client"` to the Footer component unless it requires browser APIs — it's a static link list.
- Do NOT wrap the Footer in the `app/(app)/layout.tsx` — it belongs only on public pages.
