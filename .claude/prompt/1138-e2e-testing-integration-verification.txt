# Prompt Contract — AB#1138: E2E Testing & Integration Verification

**Story Type:** Feature (Test Coverage)
**Sprint:** Sprint 1
**Parent:** AB#1132 — Freemium Paywall & Subscription Flow
**Branch:** `feature/AB#1138-e2e-testing-integration`
**Commit format:** `test(AB#1138): <subject>`

---

## Objective

Close the remaining test gaps in the freemium paywall flow by adding integration-level
Stripe webhook tests, component render tests for upgrade UI pages, and mutation-level
habit limit enforcement tests. Predecessor stories (AB#1133–AB#1137) established pure-logic
unit tests; this story adds the higher-fidelity layer.

---

## Scope

### In Scope

1. **Stripe webhook integration tests** — extend `tests/stripe-webhook.test.ts`
   - `checkout.session.completed` → `setStripeCustomer` with `isPremium: true`, `stripeCustomerId`, `stripeSubscriptionId`
   - `customer.subscription.updated` → status mapping (`active`/`trialing` = premium), fallback user resolution via `getByStripeCustomerId`
   - `customer.subscription.deleted` → `isPremium: false`, `revokeEntitlement` call
   - Signature rejection: 401 for missing header, invalid HMAC, expired timestamp (>300s)
   - RevenueCat sync: `grantEntitlement` after checkout, `revokeEntitlement` after deletion (best-effort)

2. **Upgrade flow component render tests** — extend `tests/upgrade-flow.test.ts`
   - `/upgrade` page: two plan cards ($4.99/mo, $29.99/yr), `?plan=annual` pre-selection, `?canceled=true` message
   - `/welcome` page: "Return to App" button with `momentum://` deep link, `?success=true` success heading

3. **UpgradePrompt modal component test** — create `tests/UpgradePrompt.test.tsx`
   - Renders when `isOpen=true`, hidden when `false`
   - Close button (X) triggers `onClose`
   - Displays both plan options (Monthly $4.99, Annual $29.99)
   - Custom `context` message prop

4. **Habit limit enforcement tests** — extend `tests/paywall-ui.test.ts`
   - Free user at limit (3 active habits) → `HABIT_LIMIT_REACHED` error
   - Free user under limit → creation succeeds
   - Premium user bypasses limit entirely
   - `habits.counts` returns `{ active: number, limit: 3, isPremium: boolean }`

5. **Full suite verification** — all tests pass, coverage ≥ 80%, no regressions

### Out of Scope

- Mobile E2E tests (separate infrastructure)
- Playwright browser tests (`npm run test:ui`)
- Manual QA
- Convex dev server integration tests (real backend)
- Writing or modifying production code (test-only story)

## Constraints

- **Test framework:** Vitest + jsdom + React Testing Library
- **Coverage provider:** V8 (`@vitest/coverage-v8`)
- **Coverage threshold:** 80% minimum on new/modified test files
- **Path alias:** `@` → project root (configured in `vitest.config.ts`)
- **No real Convex calls:** All Convex functions must be mocked or logic extracted as pure functions
- **No Stripe SDK:** Webhook tests use native `crypto.subtle` for HMAC, not the Stripe library
- **Mock pattern:** `vi.mock()` calls BEFORE component imports (Vitest hoisting)

---

## Edge Cases

1. **Stripe webhook with missing `client_reference_id`** — handler logs warning but returns 200 OK (graceful degradation)
2. **`customer.subscription.updated` without metadata** — falls back to `getByStripeCustomerId` lookup; test both paths
3. **Expired timestamp** — signature valid but timestamp >300s old → 401
4. **RevenueCat sync failure** — should NOT fail the webhook; test that errors are caught and logged
5. **Premium user at limit** — should bypass limit check entirely (never counts habits)
6. **`habits.counts` with no user record** — defaults to `{ active: 0, limit: 3, isPremium: false }`
7. **UpgradePrompt with no `context` prop** — falls back to default message "Unlock unlimited habits..."
