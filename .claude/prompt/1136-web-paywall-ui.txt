## Expected Output

1. **UpgradePrompt modal** renders with two plan cards ($4.99/mo, $29.99/yr), "Save 50%" badge on annual, subscribe buttons that redirect to Stripe Checkout
2. **Habits page** shows "2/3 habits used" badge for free users; badge hidden for premium; "+ New Habit" triggers UpgradePrompt when at limit
3. **HabitStackBuilder** calls `onLimitReached` when mutation throws `HABIT_LIMIT_REACHED` instead of silently failing
4. **PricingCard** shows individual premium plans with monthly/annual toggle instead of team-only $5/mo
5. **Billing page** shows individual premium status (active/inactive) and "Manage Subscription" button (Stripe portal) alongside existing team billing
6. **Lock icons** appear on premium-gated features for free users
7. **Premium users** see no limit indicators, no lock icons, no upgrade prompts

## Edge Cases

| Case | Expected Behavior |
|------|-------------------|
| Unauthenticated user on habits page | `counts` returns `{ active: 0, limit: 3, isPremium: false }` — show empty state, not limit badge |
| User at exactly 3/3 habits | Show "3/3 habits used" badge in warning style, "+ New Habit" opens UpgradePrompt |
| User with 0 habits | Show empty state ("Plant your first habit"), no limit badge |
| Premium user | No limit badge, no lock icons, no UpgradePrompt, "+ New Habit" always opens HabitStackBuilder |
| Stripe checkout canceled | User returns to `?canceled=true` — existing cancel handling in upgrade page covers this |
| `createCheckoutSession` returns null | Show error message in UpgradePrompt, don't redirect |
| User has both team + individual subscription | Billing page shows both sections independently |
| User has no team | Billing page shows individual premium section, team section shows "Create a team first" (existing behavior) |
| `counts` query loading | Show skeleton/loading state for habit count badge, don't flash "0/3" |
