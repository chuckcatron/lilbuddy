## Scope

### In Scope
1. Create `convex/stripe.ts` with two Convex actions:
   - `createCheckoutSession` — accepts userId + plan (monthly/annual), creates Stripe Checkout Session with `client_reference_id = tokenIdentifier`, returns session URL
   - `createPortalSession` — accepts customerId, creates Stripe Customer Portal session, returns URL
2. Add `/stripe/webhook` HTTP route to `convex/http.ts` handling:
   - `checkout.session.completed` → set `isPremium: true`, store `stripeCustomerId` + `stripeSubscriptionId`
   - `customer.subscription.updated` → update `isPremium` based on subscription status
   - `customer.subscription.deleted` → set `isPremium: false`
3. Add `stripeCustomerId` and `stripeSubscriptionId` as optional string fields to the `users` table in `convex/schema.ts`
4. Add `setStripeCustomer` internal mutation to `convex/users.ts`
5. Unit tests for webhook handler and mutations

### Out of Scope
- RevenueCat entitlement sync after Stripe events (Story 3 / AB#1135)
- Web `/upgrade` and `/welcome` pages (Story 2 / AB#1134)
- Web paywall UI components (Story 4 / AB#1136)
- Mobile paywall changes (Story 5 / AB#1137)
- Stripe Price ID creation in the Stripe Dashboard (manual setup)

## Constraints

- **Convex patterns**: Read `convex/_generated/ai/guidelines.md` before writing Convex code — it overrides training data
- **Stripe SDK**: Use `stripe` package (^21.0.1) already in `package.json` — do NOT install a different version
- **Webhook verification**: Stripe webhooks use signature verification via `stripe.webhooks.constructEvent()` — do NOT use Bearer token auth (that's the RevenueCat pattern)
- **User lookup**: Always look up users by `tokenIdentifier` index (`by_token`) — this is the Clerk JWT subject
- **TypeScript strict mode**: Enabled in `tsconfig.json` — no `any` types
- **Environment variables**: Access via `process.env` in Convex HTTP actions
- **Test pattern**: Extract pure logic into testable functions — Convex mutations can't be directly unit tested without a real backend

## Expected Output

After this story is complete:

1. `convex/stripe.ts` exists with exported `createCheckoutSession` and `createPortalSession` actions
2. `createCheckoutSession` returns a valid Stripe Checkout URL with `client_reference_id` set to the user's `tokenIdentifier`
3. `createCheckoutSession` accepts a `plan` parameter ("monthly" or "annual") mapped to Stripe Price IDs
4. `createPortalSession` returns a valid Stripe Customer Portal URL
5. `/stripe/webhook` HTTP route exists in `convex/http.ts`
6. Webhook verifies `STRIPE_WEBHOOK_SECRET` signature and returns 401 for invalid requests
7. `checkout.session.completed` event sets `users.isPremium = true` and stores `stripeCustomerId` + `stripeSubscriptionId`
8. `customer.subscription.updated` event updates `isPremium` based on subscription status
9. `customer.subscription.deleted` event sets `users.isPremium = false`
10. `users` schema includes `stripeCustomerId` and `stripeSubscriptionId` as optional string fields
11. Existing RevenueCat webhook at `/revenuecat/webhook` continues to function unchanged

## Edge Cases

- **User doesn't exist yet when webhook fires**: Follow the `setPremiumStatus` pattern — create the user record if not found (see `convex/users.ts:61-68`)
- **Duplicate webhook events**: Stripe may send the same event multiple times — ensure idempotent handling (patching the same values is safe)
- **Missing `client_reference_id`**: If the Checkout Session has no `client_reference_id`, log a warning and return 200 (don't crash the webhook)
- **Subscription updated to incomplete/past_due**: Map `customer.subscription.updated` status values — only `active` and `trialing` should set `isPremium: true`
- **Webhook signature verification failure**: Return 401 immediately — do NOT process the event body
