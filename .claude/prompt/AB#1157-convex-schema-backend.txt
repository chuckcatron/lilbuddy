## Scope

### In Scope

1. Create `apps/convex/` as a new pnpm workspace package with `package.json`, `convex.json`, `tsconfig.json`
2. Initialize Convex project structure (without running `npx convex init` — manual scaffold to control output)
3. Define schema in `apps/convex/convex/schema.ts`:
   - `sessions` table with flattened SessionState fields (no nested objects — Convex-compatible)
   - `users` table skeleton (name, email, tokenIdentifier)
   - `devices` table skeleton (userId, deviceId, firmwareVersion, lastSeen, isPaired)
4. Create indexes: `by_sessionId` on sessions, `by_userId_isActive` on sessions
5. Implement Convex functions:
   - HTTP action `POST /api/bridge/update` — validates `BRIDGE_API_KEY` bearer token, upserts sessions
   - Query `sessions.getActive` — returns all active sessions
   - Query `sessions.getById` — returns single session by sessionId
   - Mutation `sessions.upsert` — create or update session by sessionId
   - Mutation `sessions.markEnded` — set isActive=false by sessionId
6. Write tests for Convex functions using vitest (mock Convex internals as needed)

## Constraints

### Pattern Conformance (MANDATORY — read before you write)

Before writing ANY new code, you MUST:

1. **Read `packages/shared/src/session-state.ts` end-to-end** — understand every field of SessionState, TokenUsage, NotificationState. The Convex schema must be a faithful flattened representation.
2. **Read `apps/bridge/src/session-store.ts`** — understand the SessionState shape the bridge produces. The HTTP action must accept this shape.
3. **Read `apps/bridge/vitest.config.ts` and `apps/bridge/src/session-store.test.ts`** — match test conventions (vitest, explicit imports, descriptive test names).
4. **Follow Convex conventions** — use `v.` validators for schema, `query`/`mutation`/`httpAction` from `convex/server`, `Doc`/`Id` types from Convex codegen.

### Flattening Rules

The bridge sends `SessionState` with nested objects. Convex doesn't support nested objects well in schemas. Flatten as follows:

- `tokens: TokenUsage` → `inputTokens`, `outputTokens`, `cacheCreationInputTokens`, `cacheReadInputTokens` (4 separate number fields)
- `notificationState: NotificationState` → `notificationState` (string: `"none"` | `"permission_prompt"` | `"idle_prompt"`) + `notificationMessage` (optional string)
- Omit `transcriptPath` (local-only, not needed in cloud)
- Omit `currentToolUseId` (bridge-internal, not needed in dashboard)
