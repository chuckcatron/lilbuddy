## Scope

### In Scope
1. Create `convex/revenuecatSync.ts` with two internal actions:
   - `grantEntitlement` — calls RevenueCat REST API `POST /v1/subscribers/{app_user_id}/entitlements/{entitlement_id}/promotional` to grant premium entitlement after a Stripe web purchase
   - `revokeEntitlement` — calls RevenueCat REST API `POST /v1/subscribers/{app_user_id}/entitlements/{entitlement_id}/revoke_promotionals` to revoke entitlement after Stripe subscription cancellation
2. Modify the Stripe webhook handler in `convex/http.ts` (lines 135-185) to call the sync actions:
   - After `checkout.session.completed` sets `isPremium: true` → call `grantEntitlement`
   - After `customer.subscription.deleted` sets `isPremium: false` → call `revokeEntitlement`
3. Handle identity mapping: extract bare Clerk `user.id` from `tokenIdentifier` (split on `|`, take last segment) since RevenueCat's `app_user_id` is the bare Clerk user ID (set at `mobile/app/_layout.tsx:26`)
4. Add two Convex environment variables: `REVENUECAT_API_KEY` (secret API key), `REVENUECAT_ENTITLEMENT_ID` (entitlement identifier, e.g., `"premium"`)
5. Graceful degradation: wrap RevenueCat API calls in try/catch — log errors but never block the Stripe webhook response. Convex `isPremium` is always set regardless of sync outcome.
6. Unit tests for the sync logic, identity extraction, and error handling

### Out of Scope
- Mobile UI changes (Story 5 / AB#1137)
- Web billing UI (Story 4 / AB#1136)
- RevenueCat→Stripe reverse sync (RevenueCat webhook at `convex/http.ts:7-60` already handles mobile→Convex)
- Changes to the RevenueCat webhook handler
- Stripe checkout or portal session creation (`convex/stripe.ts` — completed in AB#1133)

## Constraints

- **Convex patterns**: Read `convex/_generated/ai/guidelines.md` before writing Convex code — it overrides training data
- **No `"use node"`**: `fetch()` is available in the default Convex runtime. Do NOT add `"use node"` to `revenuecatSync.ts` — it would prevent co-exporting with queries/mutations if needed later
- **Identity mapping is critical**: RevenueCat `app_user_id` = bare Clerk `user.id` (e.g., `user_2abc123`), NOT the full Convex `tokenIdentifier` (e.g., `https://clerk.example.com|user_2abc123`). Extract with: `tokenIdentifier.includes("|") ? tokenIdentifier.split("|").pop()! : tokenIdentifier`
- **Graceful degradation is mandatory**: RevenueCat sync is best-effort. The Stripe webhook MUST return 200 even if RevenueCat API fails. Convex `isPremium` (server source of truth) is always set first.
- **TypeScript strict mode**: No `any` types
- **Environment variables**: Access via `process.env` in Convex actions
- **RevenueCat REST API auth**: `Authorization: Bearer {REVENUECAT_API_KEY}` header, `Content-Type: application/json`

## Expected Output

After this story is complete:

## Edge Cases

- **`tokenIdentifier` with no `|` separator**: Mobile-originated purchases pass bare `user.id` as `uid` to web `/upgrade` (see `mobile/app/paywall.tsx:71`). The identity extraction must handle both formats — if no `|` is present, use the value as-is.
- **RevenueCat API returns 404 (subscriber not found)**: The user may not have opened the mobile app yet, so RevenueCat has no record. Log a warning but don't fail — the entitlement will be picked up when the mobile app initializes RevenueCat with `configurePurchases(user.id)`.
- **RevenueCat API returns 401 (bad API key)**: Log error with enough context to diagnose (include response status, omit the key itself). Don't retry — this is a config error.
- **Duplicate webhook events**: Stripe may send the same event multiple times. Granting an already-granted entitlement is idempotent in RevenueCat. Revoking an already-revoked one is also safe.
- **`customer.subscription.updated` to non-active status**: The current webhook handler (lines 152-185) handles `updated` and `deleted` together. Only add revoke sync for the `deleted` case (where `isPremium` is definitely `false`). For `updated` with non-active status, the `isPremium` flag is set correctly but RevenueCat revocation is optional — the server is source of truth.
- **Network timeout calling RevenueCat**: `fetch()` may hang — consider setting a timeout or using `AbortController` with a 10-second deadline to avoid blocking the webhook handler.
