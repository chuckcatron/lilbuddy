### Code Quality Gates

- MUST: KISS — simplest solution that fully satisfies the requirement
- MUST NOT: leave `TODO`, `FIXME`, or stub implementations
- MUST NOT: use `any` — use proper types from `@lilbuddy/shared`
- MUST NOT: modify source files to make them "more testable" — test the public API as-is
- MUST NOT: add unnecessary dev dependencies beyond vitest + coverage-v8

### Test Quality Gates

- Tests must assert **behavior**, not just exercise code paths
- Test descriptions must describe expected behavior (`"returns file_path for Read tool"` not `"tests Read"`)
- Cover edge cases: empty objects, missing keys, non-string values, zero tokens
- Test cases required for `extractToolTarget()`:
  - Read/Write/Edit → returns `toolInput.file_path`
  - Glob/Grep → returns `toolInput.pattern`
  - Bash → returns `toolInput.command`
  - WebFetch → returns `toolInput.url`
  - Agent → returns truncated `toolInput.prompt` (120 chars)
  - ToolSearch → returns `toolInput.query`
  - Unknown tool with file_path fallback → returns file_path
  - Unknown tool with no recognized keys → returns undefined
  - Non-string input values → returns undefined
- Test cases required for token functions:
  - `addTokenUsage()` sums all 4 fields correctly
  - `addTokenUsage()` with zero values
  - `parseTranscriptUsage()` maps snake_case keys
  - `parseTranscriptUsage()` with missing keys → defaults to 0
  - `parseTranscriptUsage()` with non-number values → defaults to 0
  - `totalTokens()` returns inputTokens + outputTokens
  - `hasTokens()` returns false for all-zero usage
  - `hasTokens()` returns true when any token count > 0
